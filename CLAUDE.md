## Что это за проект

Расширение для Owlbear Rodeo для русскоязычной группы, которая играет в «Вампиры: Маскарад» по 20th Anniversary Edition (V20). Хроника: Даллас, 2005 год. Цель: 3D-кубы d10 с подсчётом успехов по правилам V20, общая лента бросков, позже лист персонажа V20 и кнопка карты.

- Репозиторий: https://github.com/GreenRadiation/owlbear-rodeo-extension-vtm-v20-dice-character-sheet-ru (публичный, ветка `main`).
- Сайт расширения (GitHub Pages, деплой через GitHub Actions): https://greenradiation.github.io/owlbear-rodeo-extension-vtm-v20-dice-character-sheet-ru/
- Манифест для установки в Owlbear: `<сайт>/manifest.json`.
- Соседний репозиторий с картой хроники и заметками: https://github.com/GreenRadiation/vtm-game-map-data-ru-dallas-2005 (локально лежит рядом, в `../vtm-game-map-data-ru-dallas-2005`). Там же `private/PRIVATE_NOTES.md` с секретами персонажа автора: ничего оттуда не переносить в публичные файлы и коммиты.

## Откуда код

За основу взят официальный [owlbear-rodeo/dice](https://github.com/owlbear-rodeo/dice) (GPL-3.0, Copyright (C) 2023 Owlbear Rodeo) со всей историей коммитов. Он подключён как remote `upstream`. Наш проект тоже под GPL-3.0: файл LICENSE и упоминание авторов оригинала должны оставаться.

Стек оригинала: React 18, MUI 5, three.js через @react-three/fiber, физика Rapier (@react-three/rapier), zustand + immer, Vite 3, TypeScript 4.6, Yarn 1. Зависимости 2023–2024 годов; обновлять их только отдельной задачей, не попутно.

## Об авторе и как с ним работать

Автор — программист и разработчик игр с техническим образованием. В хронике он игрок, не мастер. С SDK Owlbear до этого проекта не работал.

- Общайся на русском и на «ты», коротко и по делу. Без эмодзи. Списки и таблицы использовать можно.
- Глубокие технические вопросы приветствуются. Задавай их пачкой, одним сообщением.
- Вопросы по правилам и хоумрулам автор сам решить не может: формулируй их так, чтобы он мог переслать мастеру.
- Решения, которые легко отменить, принимай сам и коротко сообщай, что сделал. Спрашивай только тогда, когда без ответа нельзя двигаться дальше.
- Автор ценит фактчек. Если не уверен в правиле V20 или в поведении SDK, так и скажи и предложи проверить.
- Экономь токены: не читай бинарные ассеты и большие файлы целиком.
- Интерфейс расширения русский. Комментарии в коде на английском, как в оригинале.

## Как устроен код (унаследовано от dice)

Три HTML-точки входа, все собираются Vite:

| Страница | Скрипт | Что делает |
|---|---|---|
| `index.html` | `src/main.tsx` | Попап по action-кнопке: лоток, выбор кубов, бросок |
| `background.html` | `src/background.ts` | Фоновая страница: открывает невидимый поповер для чужих бросков |
| `popover.html` | `src/popover.tsx` | Мини-лотки других игроков в правом нижнем углу |

Папки в `src`: `plugin` (всё, что касается SDK Owlbear), `controls` (UI и zustand-сторы выбора кубов и истории), `dice` (бросок, физика, стор броска), `tray` (лоток), `meshes` / `colliders` / `materials` / `previews` (геометрия, коллайдеры, PBR-материалы и превью восьми стилей кубов), `audio`, `sets` (наборы кубов), `types`, `helpers`, `tests` (тестер честности, не юнит-тесты).

Как синхронизируется бросок. Значение куба определяет физика: какая грань смотрит вверх после остановки (`helpers/getValueFromDiceGroup.ts`). Бросающий пишет в свои метаданные игрока (`OBR.player.setMetadata`, см. `plugin/DiceRollSync.tsx`) сам бросок, начальные параметры (позиция, вращение, скорости) и, когда кубы остановились, значения и финальные трансформы. Остальные клиенты получают это через `OBR.party.onChange` (`plugin/usePlayerDice.ts`) и проигрывают ту же детерминированную симуляцию Rapier у себя. Общей ленты и хранения результатов в оригинале нет: `controls/history.ts` держит в памяти несколько последних конфигураций для повторного броска.

## Соглашения этого проекта

- Все идентификаторы (ключи метаданных, id поповеров, каналы) берутся через `getPluginId()` с префиксом `io.github.greenradiation.vtm-v20/`. Префикс оригинала `rodeo.owlbear.dice/` использовать нельзя: расширения столкнутся, если в комнате включены оба.
- GitHub Pages раздаёт сайт из подпапки `/<имя репозитория>/`. Поэтому никаких абсолютных путей вида `"/popover.html"`: в коде использовать `import.meta.env.BASE_URL`, в манифесте плейсхолдер `%BASE%`.
- Манифест лежит в `manifest.template.json`, а `manifest.json` генерирует плагин в `vite.config.ts` (и в dev-сервере, и в сборке).
- Yarn на машине автора не установлен глобально. Команды: `npx yarn@1.22.22 install --frozen-lockfile`, `npx yarn@1.22.22 dev`, `npx yarn@1.22.22 build`.
- GitHub CLI стоит в `C:\Program Files\GitHub CLI\gh.exe`; если `gh` не находится в PATH, вызывать по полному пути.
- Логику правил V20 держать в чистом модуле без React и SDK и покрывать юнит-тестами.

## Ограничения SDK

Измерено 2026-10-04 диагностической страницей в настоящей комнате (мастер в Firefox, игрок в Chrome, результаты совпали):

- Метаданные комнаты: лимит ровно 16 000 байт UTF-8 на JSON всех ключей комнаты, на все расширения вместе. Кириллица стоит 2 байта на символ.
- Запись сверх лимита молча отбрасывается: `OBR.room.setMetadata` не кидает ошибку, старое значение остаётся на месте. Поэтому размер надо считать самим до записи и проверять результат чтением.
- Обычный игрок (не мастер) может писать в метаданные комнаты.
- Ключ удаляется записью `undefined`.
- Метаданные игрока и сцены принимают значение в 64 000 символов (верхнюю границу не искали). Метаданные сцены — запасное хранилище, если комнаты не хватит.
- Окно лотка (action popover) продолжает жить, когда оно свёрнуто: тот же экземпляр страницы, таймеры работают, состояние не теряется.
- Все окна расширения (лоток, фоновая страница, модальные окна и поповеры) общаются через `BroadcastChannel` и делят один `localStorage`.
- Окно Owlbear у автора около 2500×1290, у игрока около 1960×1300.
- В комнате группы стоят ещё расширения `keegan.dev.djinni` (музыка, около 350 байт в метаданных комнаты) и `com.battle-system.decked` (около 40 байт).

Не измерено и из документации:

- Запись метаданных — поверхностное слияние по ключам верхнего уровня. Если два игрока одновременно перезаписывают один ключ, одна запись теряется. Поэтому у каждого игрока свой ключ.
- «Скрытый бросок» и «чужой лист не виден» — фильтр на клиенте, не защита: данные доходят до всех клиентов. Группу это устраивает.
- Переживают ли метаданные игрока перезагрузку страницы, не проверено. Не полагаться.
- В проекте стоит SDK 1.3.9, в нём нет `OBR.broadcast` (появился позже). Пока он не нужен.
- Документация https://docs.owlbear.rodeo отдаёт 403 на curl и WebFetch, читать её нужно через браузер.
